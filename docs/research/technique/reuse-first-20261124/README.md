# Whole-request reuse before component planning

This frozen paired comparison exercises four existing-method requests: the recorded path-query
request that expanded into thirteen components, JWT algorithm and claim verification, TCP record
ownership, and filesystem containment. Both arms use the same catalog snapshot in independent
trial copies. Two repetitions and counterbalanced arm order yield sixteen planned trials.

Baseline removes only the new whole-request probe from the current bundle resolver. Candidate uses
that probe, normal native complete-document selection, original compatibility decision and shared
receipt construction. The planner/advisory editor and authorship fallback remain unchanged. The
160-generation-request cap includes repairs; completed failures are never selectively rerun.
Exhaustion produces explicit unattempted records. Sources are hashed before the first call.

Each trial freezes rendered guidance, events, component counts, unresolved components, revision IDs
and request count. A successful candidate must cover the complete requested methodology and avoid
planner/reviewer/research/author calls. Unknown target prerequisites remain conditional. A multi-test
JWT document may satisfy the whole request. Results require procedure-level inspection, not merely
component counts. No target I/O, global library writes or production operation are authorized by this
replay. Public literature research can occur only in the isolated legacy fallback if selection misses.

Contract tests cover multi-method/partial fallback and explicit failure handling; those paths are not
forced through live research in this four-case reuse comparison. Five new fast-path/error tests and
109 targeted regression tests passed. Ruff and whitespace checks passed. The paired comparison,
assembled instruction audit, receipt checks and final coverage validation are complete; see
[results.md](results.md) for measured outcomes, permission-related test reruns and limitations.
No deployment has occurred.
