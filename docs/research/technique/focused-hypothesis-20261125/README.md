# Focused hypothesis inspection and correction

The candidate follows retained source inputs through directly linked consumers, and dispatches one
pending hypothesis edit per fresh executor call. Python binds the record identifier, preserves siblings
and publication digests, then dispatches acceptance separately. A batch shares the previous agent-call
allowance; each call retains the prior per-call model-turn limit. Stalls stop the batch, and saved
corrections survive continuation. This is execution bookkeeping, not budget-aware task scheduling.

Controller schema and parse failures have an explicit internal envelope. They retain their diagnostic
instead of being validated as a semantic review. A bound hypothesis review cannot be replaced with a
prose-only conclusion. Shared semantic guidance keeps unknown prerequisites conditional and asks how
the claimed consequence differs from permitted behavior.

## Frozen paired diagnostic

`run.py` compares the pre-change shared instructions at Git HEAD with the candidate instructions.
Four source-flow fixtures cover unsafe DOM insertion, a safe text sink, a TCP source-to-command flow
and an explicitly unexamined filesystem consumer. Two editing fixtures cover authorization and
rendering consequences. Each edit fixture has two records: baseline submits both together; candidate
submits one per call. Two repetitions and counterbalanced arm order produce 24 trials and 28 expected
requests before transport repairs. The allowance is 64 generation requests, including repairs.

The study uses the production structured role transport with native/schema-tool contracts and the
configured local model, with research-specific output schemas. It does not run the full workflow:
there are no source-reading tools, durable publication mutations or target execution. Full source
snippets are supplied for the small fixtures. Consequently, successful classification cannot prove
that a worker will locate a distant sink in a large bundle. Edit quality requires semantic inspection;
structured output and completion alone do not establish correctness.

Raw prompts, outputs, source hashes and the counter are retained under
`outputs/technique_review_trials/focused-hypothesis-20261125/`. Completed trials are not selectively
rerun. Failures remain in the denominator. No production state, library or operation is modified.

## Contract verification

The final component suites passed 1,300 tests with 17 skips. Ten offline harness tests passed,
with 98.9% statement and 95.0% branch coverage for the driver. The complete repository suite passed
8,405 tests with 47 skips and 89 deselections; every changed production file exceeds both 80% floors.
Controller
dispatch tests cover HTTP, TCP and filesystem cases; successful edits, stalls, terminal failures,
allowance exhaustion and resumption; exact-record prompts, bound tool schemas, acceptance separation
and aggregation of prior outcomes. Integration tests retain prerequisite inspection and current
publication review across continuation. All 24 model trials finished using 26 requests, including
four failed authorization-edit trials. See [results.md](results.md) for semantic adjudication,
coverage details and the limitations of this diagnostic. Nothing has been deployed.
