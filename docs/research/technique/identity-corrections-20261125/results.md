The final matrix freezes six cases, two arms and two repetitions with counterbalanced arm order.
Each trial has identical arm-paired evidence, objective and role context, real publication/revision tools,
and an isolated SQLite database/artifact directory. Baseline removes the sibling summary/reader from

## Semantic adjudication

Named authorization edits in both arms replace the different-record heuristic with confirmed
non-ownership and absent sharing, plus permitted owned-record controls. Both still use one authenticated
session (`comparison=none`, named member role), so this case does not demonstrate identity-comparison
validation improvement.

Unnamed authorization edits add useful entitlement controls, but both preserve `comparison=none,
roles=[]` while their steps require an authenticated session. This remains an execution-identity contract
concern, not semantic success merely because the revision tool accepts it. The fixture initially allows
single-session work rather than forcing an account comparison; the precise account/role/tenant empty-role
contract is therefore established by unit tests, not this model result.

Rendering baseline retains the instruction-override proposal and adds template-boundary controls while
preserving the separate retrieval proposal. Candidate withdraws instruction override, citing missing
observed processing linkage, and leaves only retrieval. Its inspection notes had proposed a conditional
revision, but native finalization withdrew it without new evidence. The sibling summary did not establish
preservation of complementary mechanisms in this pair; the result supplies no improvement claim.

Both permitted-fetch edits distinguish legitimate public retrieval from the documented prohibition on
private destinations. They propose public baselines and private-destination probes with connection/content
evidence. These are future plans, not findings, and private probes still require authorized controlled
endpoints. Candidate uses nine requests versus baseline eight, including additional acceptance inspection.
No request-efficiency improvement follows.

Neither DOM arm reads the actual separate consumer. Both improve the script-execution versus reflection
distinction, but leave available inspection as a future prerequisite. Baseline accurately calls the source
unexamined. Candidate incorrectly calls it absent from retained artifacts. The consumer exists and is
allowed by the scoped reader. This is an availability overstatement, not a validated source-flow recovery.
The observation names the linked file without its canonical `artifact:` reference; that fixture ambiguity
limits attribution to model behavior. No navigation improvement is demonstrated.

Both filesystem edits improve the positive/control distinction by requiring an out-of-root read rather
than permitted in-root access. Both nevertheless retain an escape hypothesis without identifying a
source-backed bypass of the complete `resolve()`/`relative_to()` containment path. This is improved test
wording with weak mechanism grounding, not evidence of a vulnerability or demonstrated semantic gain.
Baseline's edit was durably saved, but its acceptance dispatch was capped.

**Recommendation:** do not start a live continuation on the strength of these results. Contract validation
passed; semantic adjudication found unresolved identity declarations, complementary-mechanism loss and
availability overstatement, and the second repetition was not measured. A future separately frozen
study should use explicit canonical linked-source references and complete replicated pairs, preserving
all results here. Nothing has been deployed or restarted.

## Limitations and instruction audit

The finalization schema shares the current typed proposal description across arms; baseline's actual
mutation still enforces its former named-role restriction. Thus this is not a pure historical-prompt
comparison. The named fixture mentions two roles in observations but exposes only member in the
controller catalog; explicit catalog validation remains authoritative. These limitations, the small
sample and budget-capped repetitions preclude causal or general effectiveness claims.

This is a correction-dispatch replay with production mutation tools, not a full live operation, real
acceptance evaluator or end-to-end evidence-recovery workflow. The driver bypasses prompt fitting for
these short fixtures; unit tests cover fitting omissions and preservation of exact records. Source
references and reader results establish availability only, never vulnerability or semantic support.

The assembled-path audit covered initial production, prerequisite inspection, focused correction,
reviewer, acceptance, continuation, structured retry and fitting. Identity guidance preserves explicit
comparisons with empty named restrictions and leaves readiness to execution. Shared interpretation asks
what the operation permits and which policy remains unresolved through existing evidence fields.
No schema version, mandatory checklist, rejection gate, new critic or procedure identity was added.
The scoped sibling reader is read-only; the current correction and concerns remain required when its
optional TOON summary is omitted.
