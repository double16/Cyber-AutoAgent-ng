# Explicit review-purpose contract

The preceding materiality run matched all three human labels but retained weak reasons. Its
network counterexamples often restated legitimate observations; its filesystem rejection missed
the human's clarity concern. Those outcomes remain recorded, not replaced by this revision.

New native critic interpretations and independent assessor rows now require `check_purpose`:
`prerequisite`, `legitimate_behavior` or `boundary_violation`. The model classifies the actual
draft; Python never infers purpose from prose, filenames or tool names. Mixed claims should be
split, and misleading violation labels must not be downgraded merely to avoid analysis.

Prerequisite/legitimate reviews require null counterexample judgments and empty discriminator
and control-reference fields. Actual boundary claims require booleans. A declared classification
disagreement cannot coexist with agreement; the assessor must provide referenced findings.
Existing per-decision correction and repair limits remain unchanged. No model role was added.

Older records without purpose remain explicitly unknown and retain their boolean applicability
contract. Historical scores are not rewritten. The exact [patch](revision.patch) was verified
against the preceding frozen runtime's preimage; changed source snapshots are retained as well.

and branch coverage above 80%, Ruff, and six exact-input scripted SDK preflight checks. New null
fields were exercised through native and schema-tool SDK transports without requiring an Ollama
server. Existing compatibility, correction, independent-investigation and finalization paths
remain covered. Scripted checks do not establish correct live semantic classification.
